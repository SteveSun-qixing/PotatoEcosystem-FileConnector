## 1. 开发环境配置


- Vue 渲染进程（HMR 热更新）

## 3. 如何添加新的匹配器

### 3.1 概述

匹配器是文件连接器的核心功能之一，负责自动匹配卡片和文件。所有匹配器需要实现 `IMatcher` 接口。

### 3.2 步骤

#### 步骤 1：创建匹配器文件

在 `src/core/matchers/` 目录下创建新文件：

```typescript
// src/core/matchers/MyCustomMatcher.ts

import type { CardInfo } from '@/types/card';
import type { FileInfo } from '@/types/file';
import type { MatchMode, MatchOptions, MatchScheme } from '@/types/match';
import { BaseMatcher } from './BaseMatcher';

/**
 * 自定义匹配器配置
 */
interface MyCustomMatchConfig {
  // 定义配置选项
  threshold: number;
}

/**
 * 默认配置
 */
const DEFAULT_CONFIG: MyCustomMatchConfig = {
  threshold: 0.5
};

/**
 * 自定义匹配器
 * @description 描述匹配器的功能
 */
export class MyCustomMatcher extends BaseMatcher {
  readonly name = 'MyCustomMatcher';
  readonly mode: MatchMode = 'custom' as MatchMode;  // 需要在类型中添加
  
  private config: MyCustomMatchConfig;
  
  constructor(config: Partial<MyCustomMatchConfig> = {}) {
    super();
    this.config = { ...DEFAULT_CONFIG, ...config };
  }
  
  /**
   * 检查此匹配器是否适用于当前数据
   */
  isApplicable(cards: CardInfo[], files: FileInfo[]): boolean {
    // 实现适用性检查逻辑
    return cards.length > 0 && files.length > 0;
  }
  
  /**
   * 执行匹配
   */
  match(cards: CardInfo[], files: FileInfo[], options?: MatchOptions): MatchScheme {
    // 处理空数据
    if (cards.length === 0 || files.length === 0) {
      return {
        ...this.createEmptyScheme(),
        unmatchedCards: cards.map(c => c.id),
        unmatchedFiles: files.map(f => f.path)
      };
    }
    
    // 实现匹配逻辑
    const bindings = [];
    const matchedCardIds = new Set<string>();
    const matchedFilePaths = new Set<string>();
    
    // ... 你的匹配算法
    
    // 计算置信度
    const confidence = this.calculateBaseConfidence(
      bindings.length,
      cards.length,
      files.length
    );
    
    return {
      mode: this.mode,
      confidence,
      bindings,
      unmatchedCards: cards.filter(c => !matchedCardIds.has(c.id)).map(c => c.id),
      unmatchedFiles: files.filter(f => !matchedFilePaths.has(f.path)).map(f => f.path),
      description: `通过自定义算法匹配了 ${bindings.length} 对`
    };
  }
}
```

#### 步骤 2：导出匹配器

在 `src/core/matchers/index.ts` 中导出：

```typescript
export * from './BaseMatcher';
export * from './NumberSequenceMatcher';
export * from './KeywordMatcher';
export * from './FileOrderMatcher';
export * from './SmartMatcher';
export * from './SchemeGenerator';
export * from './MyCustomMatcher';  // 新增
```

#### 步骤 3：注册到 SchemeGenerator

修改 `SchemeGenerator.ts`：

```typescript
import { MyCustomMatcher } from './MyCustomMatcher';

export class SchemeGenerator {
  // ...
  
  constructor(config: Partial<SchemeGeneratorConfig> = {}) {
    this.config = { ...DEFAULT_CONFIG, ...config };
    
    // 初始化所有匹配器
    this.matchers = [
      new NumberSequenceMatcher(),
      new KeywordMatcher(),
      new MyCustomMatcher(),  // 新增
      new FileOrderMatcher()  // 保持顺序匹配器在最后作为后备
    ];
  }
}
```

#### 步骤 4：添加类型定义

在 `src/types/match.ts` 中添加新的匹配模式：

```typescript
export type MatchMode = 'number_sequence' | 'keyword' | 'file_order' | 'smart' | 'custom';
```

#### 步骤 5：编写单元测试

在 `tests/unit/matchers/` 目录下创建测试文件：

```typescript
// tests/unit/matchers/MyCustomMatcher.test.ts

import { describe, it, expect } from 'vitest';
import { MyCustomMatcher } from '@/core/matchers/MyCustomMatcher';
import { mockCards, mockFiles } from '../../fixtures';

describe('MyCustomMatcher', () => {
  it('should be applicable when cards and files exist', () => {
    const matcher = new MyCustomMatcher();
    expect(matcher.isApplicable(mockCards, mockFiles)).toBe(true);
  });
  
  it('should not be applicable when cards are empty', () => {
    const matcher = new MyCustomMatcher();
    expect(matcher.isApplicable([], mockFiles)).toBe(false);
  });
  
  it('should match cards and files correctly', () => {
    const matcher = new MyCustomMatcher();
    const result = matcher.match(mockCards, mockFiles);
    
    expect(result.mode).toBe('custom');
    expect(result.bindings.length).toBeGreaterThan(0);
    expect(result.confidence).toBeGreaterThanOrEqual(0);
    expect(result.confidence).toBeLessThanOrEqual(100);
  });
});
```

## 4. 如何添加新的组件

### 4.1 组件结构规范

所有组件使用 Vue 3 Composition API 和 `<script setup>` 语法：

```vue
<script setup lang="ts">
/**
 * 组件名称
 * @description 组件描述
 */
import { ref, computed, onMounted } from 'vue';
import { useI18n } from 'vue-i18n';

// 定义 Props
const props = withDefaults(
  defineProps<{
    /** 属性说明 */
    propName: string;
    /** 可选属性 */
    optionalProp?: number;
  }>(),
  {
    optionalProp: 10
  }
);

// 定义 Emits
const emit = defineEmits<{
  /** 事件说明 */
  'event-name': [value: string];
  /** 另一个事件 */
  'update:modelValue': [value: number];
}>();

// 国际化
const { t } = useI18n();

// 响应式状态
const localState = ref('');

// 计算属性
const computedValue = computed(() => {
  return props.propName.toUpperCase();
});

// 方法
function handleClick() {
  emit('event-name', localState.value);
}

// 生命周期
onMounted(() => {
  // 初始化逻辑
});
</script>

<template>
  <div class="my-component">
    <!-- 模板内容 -->
  </div>
</template>

<style lang="scss" scoped>
.my-component {
  // BEM 命名规范
  &__header {
    // ...
  }
  
  &__content {
    // ...
  }
  
  &--active {
    // ...
  }
}
</style>
```

### 4.2 添加步骤

#### 步骤 1：创建组件文件

在 `src/renderer/components/` 对应目录下创建：

```
components/
├── card/          # 卡片相关组件
├── file/          # 文件相关组件
├── binding/       # 绑定相关组件
├── scheme/        # 方案相关组件
├── graph/         # 图形相关组件
├── common/        # 通用组件

```

#### 步骤 2：导出组件

在对应目录的 `index.ts` 中导出：

```typescript
// src/renderer/components/common/index.ts
export { default as MyNewComponent } from './MyNewComponent.vue';
```

#### 步骤 3：使用组件

```vue
<script setup>
import { MyNewComponent } from '@/renderer/components/common';
</script>

<template>
  <MyNewComponent
    prop-name="value"
    @event-name="handleEvent"
  />
</template>
```

```bash
# 监视模式

# 生成覆盖率报告

```

### 6.3 编写测试

```typescript
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest';

describe('ModuleName', () => {
  // 测试前准备
  beforeEach(() => {
    // 设置测试环境
  });
  
  // 测试后清理
  afterEach(() => {
    // 清理测试环境
    vi.restoreAllMocks();
  });
  
  it('should do something', () => {
    // 准备
    const input = 'test';
    
    // 执行
    const result = functionToTest(input);
    
    // 断言
    expect(result).toBe('expected');
  });
  
  it('should handle async operations', async () => {
    const result = await asyncFunction();
    expect(result).toBeDefined();
  });
  
  it('should mock dependencies', () => {
    // 模拟依赖
    const mockFn = vi.fn().mockReturnValue('mocked');
    
    // 使用模拟
    expect(mockFn()).toBe('mocked');
    expect(mockFn).toHaveBeenCalled();
  });
});
```

## 8. 代码规范

### 8.1 TypeScript 规范

- 使用强类型，避免 `any`
- 为所有导出的函数和类添加 JSDoc 注释
- 使用接口定义对象结构
- 使用类型别名定义联合类型

```typescript
/**
 * 函数说明
 * @param param1 参数说明
 * @returns 返回值说明
 */
export function myFunction(param1: string): number {
  // 实现
}
```

### 8.2 Vue 组件规范

- 使用 `<script setup>` 语法
- Props 和 Emits 使用类型定义
- 提供合理的默认值
- 添加组件文档注释

### 8.3 命名规范

| 类型 | 规范 | 示例 |
|-----|------|------|
| 文件名（组件） | PascalCase | `CardList.vue` |
| 文件名（工具） | camelCase | `fileUtils.ts` |
| 类名 | PascalCase | `NumberSequenceMatcher` |
| 函数名 | camelCase | `calculateSimilarity` |
| 常量 | SCREAMING_SNAKE_CASE | `DEFAULT_CONFIG` |
| CSS 类名 | kebab-case (BEM) | `card-list__item` |

### 8.4 Git 提交规范

使用约定式提交：

```
<type>(<scope>): <subject>

<body>

<footer>
```

类型：
- `feat`: 新功能
- `fix`: 修复 Bug
- `docs`: 文档变更
- `style`: 代码格式
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具

示例：
```
feat(matcher): add CustomMatcher for special matching logic

- Implement CustomMatcher class
- Add unit tests
- Update SchemeGenerator to include new matcher

Closes #123
```

## 9. 常见问题

### 9.1 开发环境问题

**Q: npm install 失败**

A: 尝试以下步骤：
```bash
rm -rf node_modules package-lock.json
npm cache clean --force
npm install
```

**Q: Electron 启动报错**

A: 检查 Node.js 版本是否符合要求（>= 18.0.0）

### 9.2 构建问题

**Q: 构建失败，提示类型错误**

A: 运行类型检查：
```bash
npm run type-check
```
修复所有类型错误后再构建。

**Q: 构建产物过大**

A: 检查是否有不必要的依赖被打包，使用 `vite-plugin-visualizer` 分析。

### 9.3 测试问题

**Q: 测试运行失败**

A: 确保测试环境正确设置：
```bash
npm run test -- --reporter=verbose
```

**Q: 组件测试找不到模块**

A: 检查 `vitest.config.ts` 中的路径别名配置。
